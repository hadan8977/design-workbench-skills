# Design Apple

Use a clear claim, purposeful imagery, generous space, and consistent geometry for the Apple-inspired direction requested by the user. Adapted from Yu Apple by 廷宇; see [source notes](references/source.md).

Follow the [shared skill map](../design-lead/reference/skill-map.md). This specialist supplies a chosen aesthetic; it does not impose it on unrelated work. User constraints and approved brand references take priority over sample colors, fonts, and layouts.

## Select the output mode

- **Website or product interface:** read [visual language](references/visual-language.md), then use [design-lead](../design-lead/SKILL.md) for composition, responsive behavior, interaction, and validation. Translate visual principles to the actual viewport and task. Do not copy slide dimensions, slide-sized type, or presentation navigation into normal UI. Use [design-material](../design-material/SKILL.md) only when glass or fluid materials are part of the direction.
- **Deck, proposal, or keynote-style narrative:** read [deck workflow](references/deck-workflow.md) and visual language. For HTML, PNG, or PDF production, read [tooling](references/tooling.md). For required editable PPTX, Google Slides, or an existing template, use the host's presentation workflow with this skill as style guidance. The bundled renderer has no editable PPTX generator.
- **Local revision or export:** preserve approved copy, content, and geometry. Load only relevant references. Do not restart discovery, require new sample approval, or export extra formats by default.

Infer the mode from the requested artifact and project. Ask only if output ambiguity materially changes the work; continue independent analysis while resolving it. Match the user's language and retain quotations and exact wording requests.

## Working principles

1. Decide what the audience should understand, believe, or do. A slide needs a memorable claim; an operational screen needs a clear task and visible controls.
2. Remove duplicated premises before shrinking type. Use diagrams for relationships; imagery must provide evidence, context, metaphor, process, or a deliberate pause.
3. Keep fonts, spacing, baselines, radii, and emphasis coherent. Composition follows content rather than repeating one card grid.
4. Separate verified facts, judgments, proposals, future visions, and generated illustrations. Visual confidence cannot turn an idea into evidence.
5. Keep titles, body copy, labels, data, and diagrams editable in native text or vectors where supported. Generate separate assets when useful.
6. Use available, appropriately licensed fonts and assets. Check actual line breaks after substitution; no Apple fonts or third-party brand assets are bundled.

For native iOS or macOS work, use available platform guidance and current authoritative documentation as needed. Yu Apple's presentation style does not establish Apple HIG compliance. This collection is not affiliated with Apple Inc.

## Verify the requested result

For interfaces, inspect the rendered view at relevant sizes, text contrast, keyboard focus, task states, and content fit. Preserve discoverability and density where real workflows need them.

For decks, inspect overview pacing and each affected page at full size: claims and evidence, repeated content, alignment, image crops, source labels, font substitution, overflow, and export fidelity. Refresh dependent previews and exports after changes to avoid version mixing. Automatic checks locate problems; they do not replace visual review. Report what was produced, what was actually checked, and concrete limits.
